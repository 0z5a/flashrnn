# FlashRNN1 and competing recurrent baselines

"FlashRNN1" denotes the original [FlashRNN paper](https://arxiv.org/abs/2412.07752) and [NX-AI implementation](https://github.com/NX-AI/flashrnn), pinned here at `0b84fc30120ecccbde97976bc5b086f3215572d2`; it is not a separately released version-1 package. Its public backend keys at that revision are `vanilla`, `cuda`, `cuda_fused` and `triton_fused` (the README's `triton` spelling is not the dispatcher key). Keep each backend as a distinct result, with its own supported cells and numerical gate.

The code links above pin observed repository HEADs for identification. The small existing ParaRNN dense-component check does not qualify its full package; Haste's native CUDA library and the DEER package have not been run here. Before timing another implementation, archive its source/weight hashes and actual build/runtime, then pass identical-shape numerical checks. Literature speedups are historical context, never entries in our [measured E2E speedup matrix](full-model-e2e-speedups.md).

For same-model inference, pair baseline and candidate on one GPU with identical checkpoint, prompt, generated length, model batch `1/4/16/32/64`, request concurrency `1/8/32/64/128`, dtype, state/cache/output contract and serving scheduler. Count required transforms, dispatch and synchronization in both paths; report generated tokens/s (forecasts/s for TiRex), latency distribution, peak memory, paired AB/BA speedup and its 95% interval. Long-sequence training (DEER/ParaRNN) is a separate table with identical forward/backward loss and optimizer step; sparse and adapted-cell studies require their own matched controls. Unsupported shapes remain explicit gaps. The [18-family registry](model-coverage.md) supplies each model's own fused author/FLA/ONNX baseline; FlashRNN1 does not implement those different state equations.
